## 一、产品定位

一个**本地可用、也可一键上线**的塔罗占卜网页：用户带着问题来，选牌阵、亲手洗牌抽牌翻牌，获得结合自己问题的 AI 个性化解读，并可回看历史记录。

核心体验三要素：
- **仪式感**：洗牌动画、牌扇抽牌（用户亲手点，不全自动）、3D 翻牌
- **个性化**：AI 结合具体问题解读，而非千篇一律的牌义罗列
- **可留存**：占卜日记（localStorage，含完整 AI 解读）

## 二、三个关键初始决策（2026-08-03 定）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 产品形态 | **单文件网页** | 塔罗是内容型应用、逻辑轻；双击即用 + 静态托管即上线；零依赖不过时 |
| 牌义解读 | **AI 实时解读** | 个性化是核心卖点；内置精简牌义仍保留（双用途：prompt 上下文防幻觉 + 无 Key 兜底） |
| 牌面美术 | **公版韦特牌图** | Rider-Waite-Smith 1909 已过版权保护期（公有领域），最经典、用户认同感最强 |

备选方案（当时未选，未来可再议）：结构化前端项目（Vite+React）、桌面应用（Electron/Tauri）、代码绘制 SVG 牌面。

## 三、技术方案

```
tarot/
├── index.html          ← 全部 HTML/CSS/JS（单文件，~1250 行）
├── images/             ← 78 张牌图（m00-m21 / w,c,s,p 01-14，共 ~16MB，480px 宽）
├── scripts/
│   ├── download-images.mjs / .sh   ← 图片下载（.sh 为实际使用版）
│   ├── retry-missing.sh            ← 幂等补下载
│   └── smoke-test.cjs              ← 冒烟测试（桩 DOM）
├── CLAUDE.md           ← 给未来 Claude 会话的上下文
└── docs/PROJECT.md     ← 本文档
```

- **纯原生 JS**，无框架无构建
- **随机**：`crypto.getRandomValues` + Fisher-Yates 洗牌（不用 Math.random）；抽牌时 50% 逆位
- **存储**：localStorage（`tarot.settings.v1` / `tarot.records.v1`，记录上限 200 条）
- **抽牌交互**：桌面端 78 张弧形牌扇（transform-origin 远离圆心法）；移动端降级为横向滑动牌带（matchMedia 639px 分界）
- **翻牌**：CSS 3D `rotateY` + `preserve-3d` + `backface-visibility`；横压牌通过 `--rot` 变量叠加 `rotate(90deg)`
- **图片缺失兜底**：`<img onerror>` 给容器加 `.noimg`，自动切换为牌名占位卡，永不出破图

## 四、AI 解读方案（BYOK）

- 用户在 ⚙ 设置中填 `API 地址 + 密钥 + 模型`，存 localStorage，浏览器直连
- 采用 OpenAI 兼容 `/v1/chat/completions` 格式（DeepSeek/Kimi/通义/OpenRouter 全支持）
- 预设：DeepSeek `https://api.deepseek.com / deepseek-chat`（国内直连推荐）、Kimi、通义、OpenRouter
- SSE 流式解析（`data:` 行 → `choices[0].delta.content` 增量渲染 + 光标动画）
- `max_tokens` 按牌数动态：`min(1500 + count*180, 3400)`
- **上线分享时**：每个访问者填自己的 Key；或 V2 加 Cloudflare Workers 代理藏 Key + 限流

### Prompt 设计演进（重要教训）

**v1（失败）**：
- 格式示例写「位置｜牌名」→ AI 照抄"位置"二字，小标题不显示真实位置名（过去/现在/未来）
- 系统提示写"涉及健康提醒咨询专业人士"→ 模型借题发挥，整段拒绝解读 + 说教
- 用户反馈："怎么老糊弄我呢 / 什么都没给我算出来"

**v2（现行）**：
- 系统提示明确：娱乐应用、大胆给明确"牌面答案"、直接回答（含是否/倾向/时间感/二选一推荐）、禁止说"塔罗无法预测"、禁止建议咨询专业人士；免责只由页脚统一展示
- 用户 prompt 末尾压一行【位置名称】依次为：…，小标题必须原样使用
- 先 1-2 句回应问题点出整体能量 → 逐张解读（位置名｜牌名（正/逆位）小标题）→ 「综合指引」明确回答最初的问题

**教训沉淀**：给模型的格式模板中的占位词会被照抄，必须显式列举实例；免责类软约束容易被放大成拒绝，约束要写成"禁止做什么"。

## 五、牌阵系统（V2，2026-08-03）

### 牌阵清单（8 个，三档）

| 档 | 牌阵 | 牌数 | 位置 | 专属机制 |
|---|---|---|---|---|
| quick | 单张指引 | 1 | 指引 | — |
| quick | 时间之流 | 3 | 过去/现在/未来 | — |
| quick | 二选一 | 3 | 现状/选项A/选项B | AI 给明确推荐 |
| quick | 是否牌阵 | 3 | 三张（正=是倾向，逆=否倾向） | `verdictType:'yesno'`：AI 首句必须给 是/否/悬而未决；兜底数正逆位判定 |
| focus | 四季牌阵 | 4 | 春/夏/秋/冬 | `verdictType:'season'`：AI 首句必须指出应验季节；兜底按能量分（大牌2+宫廷1+正位1）取最强位 |
| focus | 关系牌阵 | 5 | 你/对方/现状/挑战/走向 | 菱形布局；AI 对照双方牌 |
| deep | 六芒星 | 7 | 过去/现在/未来/阻碍/建议/环境/结果 | 双三角布局 |
| deep | 凯尔特十字 | 10 | 现状/挑战(横压)/根基/过去/目标/近未来/自我/环境/希望与恐惧/结果 | 十字+权杖柱布局；第 2 张横压第 1 张（`cross:true`，翻开后可点击穿透到下层牌） |

### 布局引擎
- 牌阵配置带 `layout:[[col,row],…]`（与 positions 下标对齐）→ 翻牌页 CSS Grid 按坐标排布
- 无 layout 的牌阵 → flex 横排
- 移动端（<640px）统一降级为双列流式 + 「序号·位置名」标签芯片
- 选择器里用 layout 坐标生成点阵形状预览

### AI 自适应
- 每段长度：≤3 牌 80-120 字 / ≤5 牌 60-90 字 / >5 牌 40-60 字；综合指引 ≤3 牌 100 字、其余 160 字
- 每个牌阵的 `verdict` 字段以【特别要求】注入 prompt（位置呼应、对照关系、判定要求）

## 六、美术方案

- **牌面**：Wikimedia Commons 公有领域 RWS 1909 扫描件，`Special:FilePath/<文件名>?width=480` 取 480px 缩略图
  - 大牌文件名：`RWS_Tarot_XX_Name.jpg`（注意 Judgement 拼写）；小牌：`Wands01-14 / Cups / Swords / Pents`
  - 本机网络：Commons **API 被墙**（node fetch 失败），`Special:FilePath` 可用 curl 直连
  - 下载脚本带重试；`retry-missing.sh` 幂等补漏（首轮 62/78，补一轮到 78/78）
- **牌背**：手写 SVG（星月几何纹，金色+深紫），JS 模板字符串复用，无版权风险
- **主题**：午夜蓝/深紫底 + 金色点缀、衬线标题、CSS 星空粒子、响应式

## 八、安全态势评估（2026-08-03 结论）

- **服务崩溃风险 ≈ 0**：GitHub Pages + Fastly CDN 承载，无自有服务器可被打；软限制为 100GB/月流量
- **API 密钥暴露面 = 0**：仓库无任何密钥；BYOK 模式下密钥只存在于各访问者自己的浏览器 localStorage；GitHub token 只在用户本机 gh CLI
- **真正需要守的**：GitHub 账号本身（建议开 2FA）；未来加了后端代理后，Key 放服务器环境变量 + 按用户配额限流
- 已知骚扰面：垃圾 Issue/PR（Settings 可关）

## 九、商业化路线（2026-08-03 共识）

成本锚点：一次 10 牌解读 ≈ 2 分钱（DeepSeek），毛利极高，瓶颈在流量不在成本。

四步走：
1. **免费验证**（进行中）：GitHub Pages 免费站引流；优先做 Canvas 结果分享图（病毒传播点）
2. **微信小程序 + 流量主广告**：个人主体可注册；定位"娱乐/自我探索"避开封建迷信红线；激励视频广告解锁深度解读，广告费覆盖 API 成本；需加 Key 代理（Cloudflare Workers + 配额）
3. **付费**：个体工商户（免费办理）→ 微信支付商户号 → 安卓小程序内购 / iOS 走公众号 H5（苹果禁止 iOS 小程序虚拟支付）
4. **原生 App**（收入验证后）：iOS 开发者 $99/年 + IAP；国内安卓商店需软著（自办 ~300 元 1-2 月 / 代理 ~1000 元）

配合动作：后端与支付逻辑放私有仓库（GitHub Pro $4/月可私有仓用 Pages，或迁 Cloudflare Pages 免费支持私有仓）。
